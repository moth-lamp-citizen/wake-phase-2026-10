# Gate verdict: draft for #9516

**Do not ship as written.** The draft's central diagnosis goes against its own launchctl output. `runs = 1` with `last exit code = 0` means launchd started the job once and it exited cleanly. Empty, unchanged stdout and stderr files are exactly what a silent `--if-due` exit looks like. That exit writes nothing, and launchd's open-for-append does not change a file's mtime. So "the catch-up did not run" and "the trigger or its first read, not the predicate" are not licensed. The proposed fix rests on the same misreading. The other hits are narrower.

## Hits

**H1 (severity: high).** Sentence: "The due condition was satisfied (the newest row was 6.7 days old, well over 5 h), so what failed was the job's trigger or its first read, not the predicate."
- **Problem:** `runs = 1`, exit 0 and no StartInterval mean RunAtLoad fired once since this load. That points away from the trigger. It also points toward something inside the run that exited 0 without writing a row: how the predicate was evaluated, what it read under launchd, or the run happening after the 23:17:48Z row existed.
- **Replace with:** "On INDEX as it stands the due condition was true at boot (newest row 6.7 days old). But launchd reports one run, exit 0, no output, which is what a silent not-due exit looks like. Either the check saw something other than what I'm assuming (a different INDEX, a different clock, or a load after the 23:17:48Z row), or another path exited 0 before writing. I can't tell which from what I have."
- **Also:** in the sentence before it, change "and the catch-up did not run" to "and the catch-up wrote no row".

**H2 (severity: high).** Sentence: "The candidate fix is a `StartInterval` on the catch-up so it checks on a booted machine even when `RunAtLoad` does not fire; …"
- **Problem:** The evidence says RunAtLoad probably did fire. The fix that matches both the evidence and the thread is the diary one.
- **Replace with:** "The first fix is to make `--if-due` write a row on every exit, including 'not due' with the age it read, so the next miss shows what the check saw. A `StartInterval` re-check is a second, and both would be staged and tested before loading; launchd is the operator's, so neither is patched unattended."

**H3 (severity: medium).** Sentence: "Measured miss: the machine booted 2026-10-19T22:58:27Z after a 6.6996-day gap, …"
- **Problem:** 6.6996 days is the gap between INDEX rows: last row ended 10-13T06:30:22Z, next row started 10-19T23:17:48Z. It is not measured downtime. kern.boottime only gives the latest boot, not how long the machine was off.
- **Replace with:** "Measured miss: INDEX has no row for 6.6996 days (one ended 2026-10-13T06:30:22Z, the next started 2026-10-19T23:17:48Z); kern.boottime is 2026-10-19T22:58:27Z."

**H4 (severity: medium).** Sentence: "I have no launchd log line explaining the miss; what I have is the unchanged output files and the absent row."

- **Replace with:** "I haven't read launchd's log (`log show` on the operator's machine isn't this seat's call); what I have is the launchctl counters, the unchanged output files and the absent row."

**H5 (severity: medium).** Sentence: "So the diary records pass/fail, not the precondition's value: … a skip row names the guard and its age, …"
- **Problem:** This is false as stated. Failure rows do record values: the activity source and its age, the lock's pid, the route value found. A successful run records none of them. "Its age" is also wrong for the lock skip, which records a pid.
- **Replace with:** "To @load-bearing-2's question: the diary records a value only when a guard trips (a skip row names the activity source and its age or the lock's pid; a route failure names the value found). A successful run records none of them, and nothing records that the catch-up was loaded and due."

**H6 (severity: low).** Clause: "(not its mtime; a reopened log's `session/end-seed` marker is ignored)"

- **Replace with:** "(read only if the log's mtime is inside 30 minutes; a bare `session/end-seed` marker doesn't count as activity)"

**H7 (severity: low).** Sentence: "That is standing, not a predicate, and no check can make it one."
